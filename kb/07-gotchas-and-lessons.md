# 07 – Gotchas and Lessons Learned (read before editing the theme)

## Firmware / chip behavior
1. **"No Compatible Firmware" on upload** means the theme references a field the firmware doesn't support. Find it by bisecting: build variants that remove suspect fields one at a time. Culprit found: **Heating Time Done (353173506)**.
2. **Puff Time can't be displayed.** Theme Designer saved its ID as `0`, and setting it as a Field source **crashes Theme Designer** (InvalidOperationException). On the mod, the field renders blank.
3. **Live ohms (1048642) and atomizer amps (131138) read 0** when idle after boot **and during the first session after power-on**, even while the cup is heating. **Don't use them to detect "no atomizer."** Every attempt gave false positives on the first fire. There's no field that reports atomizer presence before firing.
4. With **no atomizer**, fire still enters the session state (no power flows). The chip's own Status says "No Atomizer."
5. **Status Displayed (1048582)** is true at boot (blank text) and for about 1s after firing. A `Status` element placed **inside a conditional** rendered **blank**. Only an **unconditional `<Status/>` in its own control** shows the text ("Firing," "No Atomizer").
6. The **Status element paints an opaque background** when active, covering anything beneath it. **Labels also paint opaque backgrounds**, while Pictures with transparency don't. Overlapping controls produced missing boxes and hidden text.
7. The Status element **also shows the `Status="…"` help text** of whatever control is highlighted, and it got cut off. Strip all help-text attributes.
8. **`Status Color` works** (the reddish amber "Firing" on v0.24). The earlier blank-text failure was caused by putting it in a conditional, not by the color.
9. Built SemiBold **Small** needs **≥19px** control height for Status text, or the tops of the letters get clipped (v0.21 → v0.22 fix).
10. Fire on non-main screens = **back one level** (not home) on this firmware.
11. With **ohm lock on**, the new-coil screen **doesn't appear** when the atomizer is swapped.
12. Fields **10 and 266 are User Toggles 1 and 2**, not step-size settings (they were mislabeled early on, which is why they "did nothing"). See `05`.
13. A populated **Localization** block forces d/M/yy. Clear it for US dates.
14. Session Mode needs **international firmware**. The theme won't upload without it.

15. **Fields wrap.** A value wider than its control wraps onto a second line, and anything past the control's height is cut off. Theme Designer shows this; the local preview (`render.py`) does not. Size controls from measured glyph widths.
16. **Pure black picture pixels are drawn as transparent,** and a **full-screen (80×160) picture is not drawn at all** while firing. To take over the screen, give every other control a Hidden variant instead.
17. **Controls redraw in layers while firing.** Live (`UpdateLive`) controls repaint over static ones. A "takeover" only works if every other control hides itself and is live.
18. **The Status element paints a solid background almost constantly,** even with no message. Never overlap it with anything you want visible; give it its own row.
19. **Two memory pools.** Images and fonts use **off-board** memory; controls and condition variants use **on-board**. Check both with Theme Designer → Space Used, on the **DNA75C** (least room). Recolored images are expensive off-board; text color variants are cheap.
20. **Evolv's large font (24 px) has only ~56 characters.** It lacks I, G, E, D, L, U and more. Use it for numbers, or synthesize missing glyphs.
21. User Toggles are **not** saved in `.ecig` exports; they live on the device.
25. **Generate a condition in Theme Designer and read the XML, rather than guessing the encoding.**
    On 2026-10-30 a per-cup warning written as `AND(profile == 1, ohms > 0.4)` never fired, and the
    conclusion drawn - after a probe build that isolated the AND - was that operator 64 is unsupported.
    It is not. Saving the same condition from the tool produces **exactly** that structure, operator 64
    and all. What differed was one child: the tool compiles `=` to **operator 4**, while the hand-
    written version used **129**. The structure was right and a leaf was wrong, which looks identical
    from the outside - the whole variant simply never applies. One save in the GUI would have settled
    it in minutes and saved a day of testing around a wrong theory.
28. **Reading a static field runs that type's static constructor.** `probe_pyb2.py` froze EScribe and had to be killed. It seeded a search by reading **every static field of every type** in the DEScribe assemblies - and the first touch of any static member forces the type initializer to run. That is hundreds of pieces of arbitrary vendor code, some of it blocking. The galling part: that probe deliberately read fields rather than properties *because a property getter can run arbitrary code*, and then triggered the same hazard by a different door. **A field read is only inert on an object that already exists.** Reflecting over a *type* is not the same as reflecting over an *instance*. The replacement, `probe_pyb3.py`, walks only from live objects - `Application.OpenForms` - so every type it touches is already initialized. Two habits fell out: any Device Monitor script that loops must set `Script.WillStopIfAsked` and check `Script.ShouldStop` or the Stop button does nothing (`14`), and it should carry its own time budget so a wrong guess costs seconds rather than a force-quit. Nothing reached the mod either time - the probes open no link - so a force-quit is safe, which is the one thing that made this cheap.

27. **A feature can be condemned by a test that could never have passed.** `Operator="64"` (AND) was recorded as dead on this firmware for most of a day. Every `.ecig` ever uploaded carrying an AND had operator **`129`** as its inner equality - and EScribe **zeroes the `RefValue` of any `129` compare it round-trips**, so those compares read `profile == 0` and the AND could not have fired whatever operator 64 does. The verdict was about the inner operator, not the outer one. Retested 2026-10-30 with only on-device-confirmed operators inside (`2` and `4`), each probe on **its own 2-child control** so the ceiling of #26 could not interfere, and a four-profile truth table came back **exactly as registered**: 64 is a true AND and 65 is a true OR. **When a test fails, check that every part of it was capable of succeeding** - and when a probe mixes an untrusted element with the thing under test, it measures the wrong one. Two further habits came out of it: build the probe so a *null* result is distinguishable from a *void* one (a flat variant using a proven operator is the positive control), and give each probe its own small control rather than adding variants to a loaded one.

26. **A control can hold at most 8 children, and extras are silently dropped.** The replace warning failed for a full day and three operator theories before this surfaced. The ohms readout had **11 children** - a default, six theme colors and four threshold variants - and was the only control in the theme above 8; everything else stopped at exactly 8. The last three were never evaluated, which is why both cancels and the 0.6 threshold did nothing, and why **swapping operator 129 for 4 changed nothing: those variants were not being read at all.** Dropping the six theme tints from that one control left five children and the design worked first try, verified on hardware with four profiles locked at four resistances. **Count a control's children before debugging its conditions.** **Measured 2026-10-30: 8 children renders.** The LOW BATTERY banner is the 8th child of the battery meter and it draws and persists, so the cutoff is somewhere in 9..10 and 8 is safe. That correction cost three builds: 8 had been *inferred* from where other controls happened to stop, the inference was treated as a measurement, and a whole release went out to move a warning off a ceiling that was not cutting it. **An inferred limit is not a measured one** - and this one was cheap to measure the moment anyone tried. Two corrections fell out of the same episode: operator **4** is equality and works (an isolated variant on `profile == 4` fired exactly on profile 4), and **last match wins** is correct as `04` and `10` always said - a mid-investigation conclusion that it was first-match-wins was wrong, disproved by two always-true variants where the second won.
24. **Emulate a nested AND by layering flat variants.** `Compare Operator="64"` does not work (`10`), so a condition like "red only on profile 1 above 0.6" has to be built from the last-matching-wins rule instead. The replace warning does it with five layers: %s. Walk it through: an XL at 0.464 goes red on the first layer, then back to white on the cancel, then stays white because it is under 0.6; an XL at 0.65 ends red; a Quest at 0.5 goes red on the first layer with no cancel to catch it. **Cancel the profiles that share a physical cup** — XL CLEAN (profile 3) runs the same cup as XL, so without its own cancel an XL would false-alarm on the cleaning profile. The cost is that the cancel layer sets an explicit color, so on the Color Themes home screen the resistance reads white rather than its theme color across the XL's healthy range. Accepted deliberately: one red warning per cup matters more than that row's tint.
23. **A bare `<` or `>` anywhere in a text node makes EScribe refuse the whole file** with a blunt "Failed to open file" and no detail. Hit on 2026-10-30 by writing a threshold into a theme's `<Comments>` as `ohms<0.9`: legal-looking prose, illegal XML, because `<` opens a tag. Escape as `&lt;` / `&gt;` or word it as "above" and "below". **Validate the whole document, not just the screens** — the build script parsed each embedded `UIDesign` and passed, because the broken text was in the outer file. `ET.fromstring()` on the complete `ECigTheme.xml` catches it in a second.
22. **The ohm lock is a flag, not a snapshot; cold ohms (17825794) is what it holds.** Pressing the lock does *not* capture the resistance showing at that moment — it records "locked", and whatever is later written to cold ohms is what stays locked. Cold ohms is written by **accepting** the prompt (YES), which commits the pending reading from **1048579**. So **either order works**: LOCK then YES and YES then LOCK both end up locked on the new value, confirmed on a DNA100C 2026-10-30 (High Contrast, LOCK then YES). What fails is **locking without ever committing a reading** — the published configs ship `EvolvWDColdOhms = 0` on every slot, so locking and then answering NO, or leaving the prompt, holds that 0. That was the "locks at 0" report of 2026-10-30, and an earlier model that blamed the *order* of the two presses was wrong. Both new-coil lock controls are therefore guarded — default `<Hidden/>` with the real element carrying `<Compare Operator="1" Field="17825794" RefValue="0" />` on an `UpdateLive` control — so the lock cannot be reached until **cold ohms itself** is non-zero. **Gate on the committed value, not the pending one.** The first version of this guard tested 1048579, the pending reading, which still let lock-then-NO hold the shipped 0; testing the field the lock actually holds closes that by construction, because the only thing you can lock is a resistance the mod has already stored. Note there is no action that locks and `<Action>` takes a single child (`10` §1.7), so a one-press "accept and lock" is not expressible — a Toggle behind this guard is the closest the format allows.

## Theme building
- Explicit `Color="(1, 1, 1, 1)"` on selectable items keeps text **white on the white highlight** (invisible). Omit the color for default white. **This bites conditional variants too, which is not obvious: `v1.2.07` of High Contrast had to be recut because the replace warning's *cancel* layer set explicit white on the profile name - a selectable control - so the one profile the warning was meant to leave alone showed nothing at all (`09`, 2026-10-30). The cancels were inherited from Color Themes, where the background is dark and white is right. **A color that is correct in one theme is not automatically correct in another**, and a cancel layer is the easiest place to forget that, because it only shows on the profiles nobody is looking at. **The mechanical test, added to `tools/check-theme.py` 2026-10-30: a control is selectable - and therefore drawn on the white highlight - when it carries an `Action` or an **editable** `Setting`, meaning one without `ReadOnly="1"`. The profile name qualifies because selecting a profile is what it does. Checked against the four remaining white cancels in both themes: all are `ReadOnly` with no `Action`, so none of them can hit this.**
- White icons vanish on a white highlight, so **outline them in 1px black**.
- Fonts: render or bitmap at the target pixel size. Horizontal condensing caused blur, and "pixel-hard" thresholding at small sizes was unreadable. Evolv's own Built SemiBold.
- The ChildScreen index is **design ID − 1**, not list position.
- Keep the zip entry `ECigTheme.xml`, UTF-8 BOM, and `\r\n` inside screen XML.
- Previews: the local Python renderer (`render.py`) is approximate. Theme Designer's preview is reliable **for layout only** - it appears to draw the **last variant of a control regardless of its condition**, so a conditional color looks permanently on (`15`). On-device photos are the final truth.
- **Don't reproduce known characters/IP in art.** The gremlin is an original creature design (not movie Gremlins).

## Tool/process
- Theme Designer: **Add Condition → measurement** lists every field by name. That list plus labeled test files is how IDs were mapped.
- The Lightning **Quest** and Lightning **Pen** cups are different heaters with different settings.
- Pico TCR values don't transfer to the DNA. Recalibrate with the swab test.
