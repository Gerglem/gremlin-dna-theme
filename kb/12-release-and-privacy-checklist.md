# 12 – Release and Privacy Checklist

This repository is public. **Nothing that identifies the maintainer goes in it:** no names, emails, locations, employer, device serial numbers, measured personal values, or personal history. Public docs refer to "the maintainer" generically.

## Commit identity
All commits go through Claude Code on the maintainer's machine, using:
`Gerglem <91816923+Gerglem@users.noreply.github.com>`
Never commit with a real name or personal email. If history ever exposes something, replace history with a single clean commit (or delete and recreate the repo; the maintainer does deletions).

## Before every commit
1. Scan all text files **and decoded base64 inside theme, profile, and config files** for personal names, emails, and serial numbers.
2. Check images for metadata: no EXIF or GPS (resaving through PIL strips it). Files delivered by Claude carry a C2PA "Claude provided this file" tag, which contains no personal data.
3. Verify every relative link resolves, including links from live Reddit posts (`reddit/` pointer files).
4. Keep the private build kit and private notes out of the repo.
5. **No theme we publish may display `Firmware -> Serial Number`.** It is an offered source in Theme
   Designer (`15`), and a screen carrying it would print the maintainer's device serial into every
   screenshot and every photo of the mod. Check this when reviewing a new screen, not just the text.

## Sanitizing an EScribe `.ecig` export
Exports contain the maintainer's real device state. Always fix these before publishing (`DEScribe.xml` inside the zip; text values are base64 UTF-8):
- `EvolvWDColdOhms` → 0 and `EvolvWDOhmLock` → 0 for every slot. **Exports have contained the maintainer's measured cup resistances with the lock on every time.**
- `EvolvWDColdOhmsTemperature` → 70 where present.
- `EvolvATFriendlyName` (profile names), `EvolvPSPower`, `EvolvPSTemperature`, `EvolvWMEnable`, `EvolvWMTime` → the published profile values (`03`).
- `EvolvXHiddenProfile` → 1 for unused slots 5–8.
- `EvolvBatterySoftVoltage` → 3.
- `EvolvThemeTitle` correct, `EvolvThemeAuthor` empty.
- High Contrast only: `EvolvXAutoLock` → 0.
- Leave `EvolvXPassword` (FFFFF) and `EvolvPowerLockPassword` (SSS); they are Evolv defaults.
- Keep the zip entry name `DEScribe.xml`, the UTF-8 BOM, and CRLF line endings. Back up the source first, then print a slot table to verify.

## Naming and versions
- Themes: `gremlin_vX.Y_theme.ecigtheme`, the original v1.0 format. High Contrast is named for itself and versioned on its own track: `gremlin_high_contrast_vX.Y_theme.ecigtheme`. Internal builds add a **mini version**, `vX.Y.NN`, bumped on every handover and dropped at release.
- Full setups: `gremlin_vX.Y.ecig` and `gremlin_high_contrast_vX.Y.ecig`, exported by the maintainer from EScribe (themes are stored compiled inside `.ecig`, so they can't be generated by script).
- **Releasing means dropping the mini version** (`gremlin_v2.2.05.ecig` → `gremlin_v2.2.ecig`) across the files, the `<Comments>` / `EvolvThemeComments` descriptions and every link. Internal mini-versioned builds are **not pushed**.
- **When a version bumps, rename the files and update every link that names them:** landing pages, guides, `README.md`, and the "Current state" table in `00`. Bump the version inside the theme too — `<Comments>` in the `.ecigtheme` and `EvolvThemeComments` (base64) in the `.ecig` — and add a `RELEASE-NOTES.md` entry on the matching track (`../release/` or `../high-contrast/`).
- `.gitattributes` keeps `*.csv` as CRLF (`-text`); don't let tooling normalize them.

## The device serial turns up in places you would not look

The serial is the USB instance ID and must never enter this repo. Two sources found the hard way:

- **EScribe window titles.** Device Monitor's caption is `Device Monitor - <theme> - <serial>`, with the
  serial spaced into groups. Any script or screenshot that captures a window title captures the serial.
  `tools/probe_pyb3.py` printed form titles verbatim until 2026-10-30; it now prints the type name only.
- **Device enumeration output.** `USB\VID_268B&PID_0433\<serial>` (`16`).

**Before pasting any probe report, log or screenshot into the repo, search it for the serial.** The
release check greps for it, but that only catches what reaches a commit.
